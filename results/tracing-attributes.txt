    dsb.gen_ai.cost.usd             float64  0.0012024                     6.2

  THE THREE FROM 6.1 ARE SET AT SPAN CREATION AND THE SIX FROM 6.2 AT SPAN END,
  and that split is deliberate. A call that 429s or times out has no usage to
  report but must still be findable by model and provider, so the identifying
  three ride withSpan()'s `attributes` argument, which is applied before the
  callback runs. tests/observability.cost.test.js asserts both halves — the
  three at creation, and a rejected call keeping them with no usage attached.

  NONE OF THE gen_ai.* GROUP IS STABLE. Measured at 6.1 against
  @opentelemetry/semantic-conventions@1.43.0: 0 in the stable root entrypoint,
  40+ in experimental_attributes.js. These are the spec's names written as
  literals in backend/observability/index.js and pinned by a test, NOT imported
  — importing would add a twelfth runtime dependency for string constants.

  ┌──────────────────────────────────────────────────────────────────────────┐
  │ A TRAP FOR ANYONE FILTERING IN THE JAEGER UI, AND IT IS JAEGER'S, NOT     │
  │ THIS APP'S.                                                              │
  │                                                                          │
  │ gen_ai.response.finish_reasons is PLURAL in the convention and typed as  │
  │ an ARRAY, and this app sets it as one. The table above shows it as a     │
  │ `string` holding ["stop"] because Jaeger's v1 tag model has no array     │
  │ type and JSON-encodes the value. Checked against the v3 (OTLP-native)    │
  │ API on the same trace rather than assumed:                               │
  │                                                                          │
  │   "key": "gen_ai.response.finish_reasons",                               │
  │   "value": { "arrayValue": { "values": [ { "stringValue": "stop" } ] } } │
  │                                                                          │
  │ So the array survives the wire intact. THE CONSEQUENCE IS PRACTICAL:     │
  │ a Jaeger v1 tag search for finish_reasons=stop matches NOTHING. It must  │

  │ nicer was rejected — it would mean shipping a name the spec defines as   │
  │ an array carrying something else, which is worse than an awkward filter. │

C. THE COST FIGURE, AND WHAT IT IS NOT
==============================================================================

    prompt tokens (actual)   832        x $0.15/1M  =  $0.00012480
    completion tokens       1796        x $0.60/1M  =  $0.00107760
                                                       ------------
    dsb.gen_ai.cost.usd                                $0.00120240

  THE RATE IS A PUBLISHED LIST PRICE, READ FROM THE VENDOR AND DATED.

    https://console.groq.com/docs/model/openai/gpt-oss-120b   read 23 Aug 2026
      input          $0.15  per 1M tokens
      cached input   $0.075 per 1M tokens     <- NOT applied, see below
      output         $0.60  per 1M tokens

  It lives in backend/observability/cost.js, in ONE place, stamped
  `groq-list-price-2026-08-23`, and the same table prices results/
  studypack-cost.txt. A second copy of $0.15 anywhere would be §28.9's defect
  built by hand — a constant with no checksum, free to drift from the one the
  app uses.

  ⚠️  NOBODY WAS CHARGED $0.0012024. This project is on Groq's free tier and
      the real invoice is $0.00. PRIMER §8.3 wrote the honest position before
      any of this was built: token counts are real regardless of price, price
      is a multiplier applied afterwards, and the claim these numbers support
      is "per-request token cost was attributed through the pipeline" — never
      the size of a bill.

  ⚠️  AND IT WOULD BE AT OR BELOW THE LIST FIGURE EVEN ON A PAID ACCOUNT. Groq
      applies automatic prompt caching to this model at half rate on cached
      input. Nothing in this repository observes whether a call hit that cache,
      so every input token is priced at the full rate. The honest direction to
      be wrong in.

  WHY TWO ATTRIBUTES AND NOT ONE. A bare 0.0012024 in a trace UI is a
  measured-looking number with no artifact behind it, which CLAUDE.md's claim
  discipline forbids. `dsb.gen_ai.cost.rate_source` names the table and the
  date, so a reader can follow the string to the file and find the URL, the
  rate and the free-tier warning. A test asserts the pair travels together.

  WHY THE dsb. PREFIX. There is no standard attribute for cost at any maturity
  level — not in the stable set and not in the experimental one. Squatting on
  a gen_ai.* name a future spec might define differently was refused; the
  prefix says "this project invented this" at a glance beside seven attributes
  that did not have to be invented.

  AN UNPRICED MODEL IS LABELLED, NOT BLANKED. If MODEL moves to something
  cost.js does not price, the span reports `unpriced:<model>` and omits
  cost.usd entirely — never 0, because zero is a real price. §23.3's rule
  applied to a span instead of a database row: an unexplained absence and
  broken instrumentation look identical, and a labelled one does not.

  WHAT THIS IS NOT: a truncation rate at the new ceiling, and not a citation

  truncation rate remains UNMEASURED, exactly as §35.3 and §37.6 say.

  61% OF THE COMPLETION IS REASONING, AND IT IS BILLED AT THE OUTPUT RATE.
  1060 of 1796 tokens here, and 61.0% across the whole 30-call gen-v5 ledger,
  which is not a coincidence worth reading into from two points. Groq counts
  reasoning inside completion_tokens, so nothing is added or subtracted for it
  and it needs no separate attribute — but it is where the money goes. See
  results/studypack-cost.txt section C.

  wrote no ledger row, so no committed artifact moved.
