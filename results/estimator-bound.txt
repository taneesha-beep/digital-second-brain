D. THE COST OF MOVING THE CONSTANT

   A SMALLER DIVISOR ESTIMATES MORE TOKENS PER NOTE, SO FEWER NOTES FIT THE
   1,800-TOKEN BUDGET. That is a user-visible product change and this table is
   what it costs, measured on the committed clusters rather than argued.

   divisor     cluster under/60   worst    mean over-estimate   single under/151
   --------------------------------------------------------------------------
   4.200000        0 / 60       13               7.4%           0 / 151
   4.400000       10 / 60      -60               2.8%           0 / 151
   4.350000        4 / 60      -43               4.0%           0 / 151
   4.333333        2 / 60      -35               4.3%           0 / 151
   4.238095        0 / 60        0               6.4%           0 / 151
   4.200000        0 / 60       13               7.4%           0 / 151
   --------------------------------------------------------------------------

   THE FAILURE MODE OF AN UNDERESTIMATE IS NARROWER THAN THE TEST COMMENT SAYS,
   AND STATING IT NARROWLY IS THE HONEST THING. CONTEXT_TOKEN_BUDGET is 1,800 —
   a self-imposed budget set by the RATE LIMIT, far below this model's context
   window. So an underestimate does not overflow anything: it means one more note
   was admitted than the budget intended, and the reservation was that much low.
   The guarantee that breaks is "the assembled prompt is at most 1,800 estimated
   tokens", not "the request fits".

   WHAT THIS FILE DOES NOT ESTABLISH: the right value for a FUTURE population.
   Every row here was drawn at max_tokens 2048 and the feature ships at 4096.
   A divisor fitted on 60 calls bounds those 60 calls. §32.2's rule stands.

E. THE PRODUCT COST, BY REPLAYING THE ADMISSION LOOP

   Section D prices the ESTIMATE. This prices the CONSEQUENCE, which is the
   number the decision actually turns on: a smaller divisor estimates more
   tokens per note, so fewer notes fit the budget and a study pack gets a
   shorter cluster. Replayed over the same 60 committed clusters.

   budget 1800 tokens, seed always admitted, neighbours in rank order

   divisor      notes admitted   packs losing a note   worst loss   mean notes/pack
   ------------------------------------------------------------------------------
   4.200000          503            0 of 60             0         8.38
   4.350000          507            0 of 60             0         8.45
   4.333333          506            0 of 60             0         8.43
   4.238095          503            0 of 60             0         8.38
   4.200000          503            0 of 60             0         8.38
   4.100000          500            3 of 60             1         8.33
   4.000000          494            9 of 60             1         8.23
   ------------------------------------------------------------------------------
   baseline at the shipped 4.2: 503 notes across 60 packs

   THE ROW THAT DECIDES IT: 4.200000 AND 4.238095 COST EXACTLY THE SAME.
   Same packs affected, same total notes, and no pack ever loses more than
   ONE note at either value. So the margin between them is FREE — 4.238095
   is the tightest bound and has ZERO slack on its worst call, and 4.2 buys
   real headroom for no product cost at all.

   ZERO SLACK IS THE FRAGILITY THAT PRODUCED THIS WHOLE ENTRY. The shipped
   4.5 had min slack +1 on the 79 rows it was fitted on, 0 on all 151, and
   -97 on clusters. A bound with no margin is a bound the next population
   breaks, and "the next population" is exactly what a note-taking app is.
