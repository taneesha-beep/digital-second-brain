D. THE COST OF MOVING THE CONSTANT

   A SMALLER DIVISOR ESTIMATES MORE TOKENS PER NOTE, SO FEWER NOTES FIT THE
   1,800-TOKEN BUDGET. That is a user-visible product change and this table is
   what it costs, measured on the committed clusters rather than argued.

   divisor     cluster under/60   worst    mean over-estimate   single under/151
   --------------------------------------------------------------------------
   4.500000       27 / 60      -97               0.6%           0 / 151
   4.400000       10 / 60      -60               2.8%           0 / 151
   4.350000        4 / 60      -43               4.0%           0 / 151
   4.333333        2 / 60      -35               4.3%           0 / 151
   4.238095        0 / 60        0               6.4%           0 / 151
   4.200000        0 / 60       13               7.4%           0 / 151
   --------------------------------------------------------------------------

   THE FAILURE MODE OF AN UNDERESTIMATE IS NARROWER THAN THE TEST COMMENT SAYS,
   AND STATING IT NARROWLY IS THE HONEST THING. CONTEXT_TOKEN_BUDGET is 1,800 —
   a self-imposed budget set by the RATE LIMIT, far below this model's context
   window. So an underestimate does not overflow anything: it means one more note
   was admitted than the budget intended, and the reservation was that much low.
   The guarantee that breaks is "the assembled prompt is at most 1,800 estimated
   tokens", not "the request fits".

   WHAT THIS FILE DOES NOT ESTABLISH: the right value for a FUTURE population.
   Every row here was drawn at max_tokens 2048 and the feature ships at 4096.
   A divisor fitted on 60 calls bounds those 60 calls. §32.2's rule stands.
