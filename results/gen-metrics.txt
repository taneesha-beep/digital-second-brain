PHASE 5.4 — PROGRAMMATIC GENERATION METRICS

  Four metrics, no judge model: schema conformance, citation validity,
  citation support, empty/refusal rate. Computed over COMMITTED LEDGERS —
  this script issues no API call, needs no key and reads nothing under
  data/, so it runs anywhere and costs nothing to re-run.

  Produced by:  cd backend && npm run eval:gen -- --write

    npm run gen:v5 -- --run        (nothing completed is lost)

  ROADMAP 5.4 ASKS FOR "ALL FOUR METRICS POPULATED FOR gen-v1" AND THAT IS
  NOT POSSIBLE. gen-v1 and gen-v2 are SINGLE-NOTE generation and produce no
  citations at all — §28.12: "they need generated citations, and single-note
  generation produces none." There is no run to make and no prompt to fix:
  the five control prompts have no `source` field and adding one would edit
  the A/B control that results/gen-baseline.txt and results/gen-v2.txt
  measure.

  So the citation columns read `n/a - no citations` for the two single-note
  runs. THAT IS NOT A GAP IN THE DATA, IT IS A PROPERTY OF THE
  CONFIGURATION, and it is the device gen-schema.js already uses for
  `summarize` and `eli5`, which have no schema: n/a rather than 100%,
  because scoring an undefined thing as perfect invents a ceiling nobody
  defined and drags every average upward for free.

  Rejected: scoring gen-v1 at 100% or 0%; assigning its items a citation
  post-hoc by best lexical overlap (that is this file's own support metric
  used as the assignment rule — it would read 100% by construction and
  measure nothing, §30.5); and re-running the control prompts on cluster
  text, which still yields no citations and doubles the quota.

D. CITATION SUPPORT — A PROXY, AND IT SHIPS WITH ITS NULL
==============================================================================

  Lexical containment of the claim's terms in the cited note's terms:
  |claim n note| / |claim|. Tokenizer is utils/keywords.js — the app's own,
  retriever-INDEPENDENT so 5.7 can vary the retriever without moving the
  measuring instrument, and not a fourth tokenizer.

    items scored               126
    unscorable                   0   valid citation, no terms after stopwords

    mean                        0.284
    median                      0.273
    p10                         0.133
    rate >= 0.3                 40.5%
    rate >= 0.5                  6.3%   <- the PRE-COMMITTED cut
    rate >= 0.7                  0.0%

  THE NULL. The same claims scored against the notes in the SAME prompt
  they did NOT cite. Without it a support figure has no scale at all.

    mean vs CITED note          0.284
    mean vs OTHER notes         0.123
    GAP                         0.161   <- the number that says whether
                                        a citation carries information

    cited note is the argmax    69.8%

    by slot:
      flashcards  n=  54   cited   0.303   other   0.127   gap   0.176
      concepts    n=  72   cited   0.270   other   0.121   gap   0.150

    items citing the SEED       15.1%   label 1 of  8.7 notes
      A pack that leans on the seed used the cluster less than `notesCited`
      suggests. This is the sharper version of that number.

    argmax IS NOT A CORRECTNESS RATE. A model may legitimately cite a note
    that is not the best lexical match — that is the paraphrase mode below,
    seen from the other side. It is a countable event, not a verdict.

  WHAT THIS NUMBER IS NOT, AND BOTH DIRECTIONS ARE REAL:
    - a correct PARAPHRASE sharing no vocabulary scores zero, and that is
      NOT a hallucination;
    - a claim built from generic vocabulary scores high against ANY note in
      the cluster, so a high score is not evidence of support either.
  5.6's judge is what actually answers the question. This is the cheap
  programmatic proxy that needs no judge, which is the whole point of 5.4.

==============================================================================
G. WHAT THESE NUMBERS CANNOT SAY
==============================================================================

  NOT THE GOLDEN SET. 9 of 30 seeds, stopped by the daily cap. The
  quintile spread is printed in section F precisely because the golden set
  is 6 per quintile and a partial run has no mechanism protecting that
  balance — the seeds are called in file order, which is by id, and any
  stratification a prefix happens to have is luck rather than design.

  NO NOISE FLOOR EXISTS FOR ANY gen-v5 FIGURE. n = 1 per seed measures
  BETWEEN-SEED variation only. §28.8 measured 32.1% of `examQs` cells
  flipping verdict on a re-draw at this temperature and nothing here
  establishes the equivalent for a study pack. So no figure in sections
  C-F may be compared against a later one until repeats are bought.

  NO BEFORE. Study Pack has no single-note counterpart with citations, so
  every gen-v5 figure is a first measurement rather than a delta. §28.2
  records the confound that makes gen-v1 an unusable "before" for it, and
  §30.2 names the four variables involved.

  CITATION SUPPORT IS A PROXY (section D) and is labelled one everywhere.

  THE NEIGHBOURS ARE RETRIEVED OVER 27,325 CORPUS DOCUMENTS, not over a
  <=500-note user slice. §12.2's gap, and the seeds are Stack Exchange
  questions shaped as Notes rather than anybody's notebook.

  NOT A COMPARISON ACROSS RETRIEVERS. That is 5.7, and it is what the
  retriever parameter on buildCluster() and the stamped digest exist for.
