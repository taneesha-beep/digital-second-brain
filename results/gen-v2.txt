A. WHAT WAS RUN, AND THE TWO DENOMINATORS
==============================================================================

  §5.3a records that trec_eval OMITS queries a retriever returned nothing for,
  and that aggregating that divides by the wrong denominator. The same trap
  arrives here. It is split rather than collapsed, and BOTH rates are printed:

  cells planned          330    30 seeds x (3 JSON features x n=3 + 2 prose x n=1)
  cells completed        76

  THE RUN STOPPED ON A DAILY TOKEN CAP, AND THE COVERAGE THAT SURVIVED IS THE
  COVERAGE THAT WAS DESIGNED TO. Calls are issued REPEAT-MAJOR — every cell's
  first draw before any cell's second — precisely so a run cut short yields a
  COMPLETE n=1 pass rather than complete coverage of some seeds and none of
  others. What landed:

    distinct (seed, feature) cells   76 of 150   <- COMPLETE n=1
    cells with 2 draws               0
    cells with 3 draws               0


    seeds with all 5 features    14 of 30   <- SECTIONS B-G ARE OVER THESE

    THE FIRST PASS IS INCOMPLETE, so sections B-G run over the seeds that
    have EVERY feature rather than over every row that landed. Rows for a
    partially-covered seed are dropped from those sections — otherwise each
    feature would be scored over a different seed set, and a per-feature
    rate would partly reflect which calls happened to land before the run
    stopped. That is §28.11's weighting bug in a new shape.

    retained by length quintile   Q1:3  Q2:3  Q3:3  Q4:3  Q5:2
    The golden set is 6 per quintile, so check this spread before quoting
    any rate: the defect being measured moves along the length axis.

  Section H, which needs repeats, is over the cells that got two, and says so.
  API calls attempted    110
  API calls completed    76
  API failures           34
  DELIVERY RATE           69.1%   completed / attempted

  An API failure (429, 5xx, socket) is EXCLUDED from conformance — no
  completion exists, so nothing was generated to conform — and reported here
  instead. A model that returned garbage is a ZERO, never an exclusion.

  REASONING TOKENS — A CONFOUND ON SECTION D, MEASURED RATHER THAN NAMED
  ----------------------------------------------------------------------

  openai/gpt-oss-120b emits a reasoning chain in a SEPARATE
  `reasoning` field, so it does NOT pollute the JSON and section B is clean.
  But reasoning tokens COUNT AGAINST completion_tokens and therefore against
  max_tokens: 1024 — so they consume ceiling that a non-reasoning model would
  have spent on content, and section D's truncation rate is inflated by
  exactly this much relative to one.

  feature      calls   reasoning(mean)  (p95)   share of the 1024 ceiling

  SO SECTION D IS AN UPPER BOUND on what the shipped prompts would truncate
  at on a non-reasoning model, and the size of the overstatement is the last
  column. This is the confound priced, not the confound avoided — which is
  the better outcome, because avoiding it would have meant choosing a model
  for the measurement's convenience rather than the app's.

H. WITHIN-CELL VARIANCE — WHAT n=3 BOUGHT, AND WHETHER IT WAS WORTH IT
==============================================================================

  A cell is one (seed, feature). At temperature 0.4 repeated draws can
  disagree. THIS IS THE NUMBER 5.5 NEEDS: if cells flip on a re-draw, a small
  before/after difference is not attributable to the fix.

  n=3 WAS PLANNED AND THE QUOTA SET n INSTEAD. The run stopped on Groq's
  200,000 tokens-per-day cap after a complete n=1 pass plus part of the second,
  so NO CELL REACHED THREE DRAWS. The rows below are over cells with TWO, which
  answers the same question with less resolution: two draws can disagree, and
  the rate at which they do is what bounds 5.5's attributable difference.

  feature      cells n>=2   both conform   both fail   SPLIT
  --------------------------------------------------------------
  flashcards            0              0           0       0
  concepts              0              0           0       0
  examQs                0              0           0       0
  --------------------------------------------------------------
  ALL                   0   unanimous 0   SPLIT 0      n/a of cells

  A SPLIT CELL IS A CELL WHOSE CONFORMANCE IS NOT A PROPERTY OF ITS INPUT.
  Read the ALL row as a floor on the noise 5.5 has to clear: with two draws
  the observed split rate understates the three-draw rate, because three draws
