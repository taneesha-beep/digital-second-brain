2. WHAT THE REFERENCE ACTUALLY DOES  (probed against the installed binary)
------------------------------------------------------------------------------
  tie-break on equal scores   docid DESCENDING
    two docs tied at 1.0, only the lexicographically LATER one judged
    relevant -> ndcg_cut_1 = 1.0
    retrieval/index.js sorts ties docid ASCENDING (EVALUATION.md §7.2),
    so the two rules are opposites. Step C is what removes this.

  queries with no run lines   OMITTED from the output entirely
    qrels holds q1 and q2, run holds only q1 -> evaluate() returns ['q1']
    Aggregating that directly divides by the wrong N. Step B is what
    removes this; §9.1 scores them 0 and keeps them in the mean.

  gain formula (ndcg_cut)     LINEAR, gain = grade
    grade-1 doc at rank 1, grade-2 doc at rank 2:
      pytrec_eval             0.8597186998521972
      linear-gain prediction  0.8597186998521972   <- matches
      2^g-1 prediction (§9.1) 0.7967075809905066
    A 0.0630 difference on one query, not a rounding
    error. 2,756 of 16,678 judgments are grade 2, so this is visible
    on the real key. Step D is what removes it.

  recip_rank depth            searches the WHOLE run file
    first relevant document at rank 15:
      pytrec_eval on the full 15-deep run   0.066667  (= 1/15)
      metrics.js on the list truncated at 10 0.000000
    Both are correct about the list they were given. The reported MRR
    is therefore recip_rank@10 — the runner truncates at k=10 before
    the scorer sees anything, so agreement on the dev runs below is
    real but conditional on that truncation, not on the definition
    being depth-unbounded. Labelled MRR@10 from here on.

6. WHAT THIS DIFF DOES NOT ESTABLISH
------------------------------------------------------------------------------
  A passing check is easy to over-read, so the gaps are named here
  rather than left for someone to assume were covered.

  - The unjudgeable-query branch of §9.1 is UNTESTED. metrics.js returns
    null and excludes those queries from the mean; cooking has 0 of them
    (build-qrels.js dropped the 74 out-of-corpus endpoints at 1.3), so no
    query in either run file exercises the path. It stays covered by unit
    test only until a corpus that has some appears.
  - MRR is validated as recip_rank@10, not as unbounded MRR. §2 above
    measures the gap the truncation hides.
  - Tie ordering is bridged, not reconciled. The run files' rank column
    is not recoverable from their score column, so a TREC tool reading
    one of these files without step C's transform scores a different
    ranking than this harness intends. Measured cost at nDCG@8 is small
    but non-zero; see step B->C in each ladder.
  - Only v1-overlap is covered, on dev only. Each later rung on the
    ladder needs its own run through this script — the check is of the
    scorer, but a new retriever can produce result shapes (longer lists,
    different tie density) that this pair does not exercise.
